# Curio Design System

This document describes the design system as it actually exists in the repo today, following the Phase 1–3 design-system consolidation work (tokens, primitives, and contrast/accessibility fixes). It is generated by reading `app/globals.css` and `components/ui/*` directly — every table and example below is sourced from current code, not from the original consolidation plan.

**Scope note:** `components/AdminDashboard.tsx` is explicitly out of scope for the entire design system. It still uses pre-consolidation ad-hoc values (arbitrary Tailwind brackets like `text-[32px]`, `leading-[1.05]`, `tracking-[-0.015em]`, `mt-[36px]`, plain `border-line` instead of `border-line-strong`) and does not use any of the `components/ui/` primitives. Do not treat it as a reference implementation.

## 1. Color tokens

All color tokens are CSS custom properties defined in `app/globals.css`, set on `:root` (light) and overridden under `[data-theme="dark"]` and the `prefers-color-scheme: dark` media query (for users who haven't made an explicit choice). Each is registered in the `@theme inline` block as `--color-<name>`, which generates the corresponding Tailwind utilities (`bg-<name>`, `text-<name>`, `border-<name>`, etc.).

| Token | Light | Dark | Tailwind utility example |
|---|---|---|---|
| `--paper` | `#f1ece0` | `#17140f` | `bg-paper` — page background |
| `--paper-raised` | `#e9e2d0` | `#211c15` | `bg-paper-raised` — raised surface (e.g. active `SegmentedTabs` pill) |
| `--ink` | `#24302b` | `#ece6d6` | `text-ink` — primary text |
| `--ink-soft` | `#5b665f` | `#b0a891` | `text-ink-soft` — secondary text |
| `--ink-faint` | `#5b665f` | `#b0a891` | `text-ink-faint` — tertiary/label text |
| `--accent` | `#9c6b30` | `#d3a35f` | `text-accent` / `border-accent` — links, active states, highlight |
| `--accent-deep` | `#7a4f1e` | `#e8bd82` | `text-accent-deep` — deeper accent variant |
| `--accent-button` | `#7a4f1e` | `var(--accent)` (i.e. `#d3a35f`) | `bg-accent-button` — primary button fill only |
| `--line` | `#d8cfbc` | `#3a3226` | `border-line` — decorative dividers/section borders |
| `--line-strong` | `#8c806a` | `#6b6250` | `border-line-strong` — borders on interactive controls |
| `--danger` | `#a13f3f` | `#d97b7b` | `text-danger` — error text |

### `ink` vs `ink-soft` vs `ink-faint`

- **`ink`** — primary reading text: body copy, headline words, active/selected states (e.g. `SegmentedTabs`' active tab, `ToggleGroup`'s active chip).
- **`ink-soft`** — secondary text: supporting copy, inactive tab/chip labels, italic captions, hover targets that shouldn't compete with primary text.
- **`ink-faint`** — tertiary text: field labels, placeholders, dates/metadata, the least prominent text on a screen.

**Important current-state note:** as of the Phase 3 contrast fix, `--ink-faint` was repointed to the *same* hex value as `--ink-soft` in both themes (`#5b665f` light / `#b0a891` dark — see below). They are visually identical right now. The two tokens still exist as separate names because they mark different *semantic* roles (secondary vs. tertiary text) even though they currently render identically; call sites should keep using whichever token matches their role, not treat them as interchangeable, since a future palette change could re-diverge them. One consequence: `hover:text-ink-soft` transitions on elements whose resting state is `text-ink-faint` (e.g. `Button`'s `link` variant, `HistoryList` date labels) are currently visually inert — this is a known, approved side effect of the fix, not a bug.

### Phase 3 contrast-fix additions/changes

Three tokens were changed or added in Phase 3 to fix five measured WCAG contrast failures. Verified ratios (from `.superpowers/sdd/2026-09-19-design-system-consolidation/task-13-report.md`, independently recomputed against the final `app/globals.css` values):

| Change | Token | Before → After | Measured ratio | Requirement | Result |
|---|---|---|---|---|---|
| Darkened | `--ink-faint` | `#8a9089` → `#5b665f` (light) | `ink-faint` on `paper`, light: **5.07:1** | 4.5:1 (text) | PASS |
| Darkened | `--ink-faint` | `#7d7666` → `#b0a891` (dark) | `ink-faint` on `paper`, dark: **7.75:1** | 4.5:1 (text) | PASS |
| Added | `--accent-button` | new token, `#7a4f1e` light / `var(--accent)` dark | `text-paper` on `bg-accent-button`, light: **6.01:1** | 4.5:1 (text) | PASS |
| Added | `--line-strong` | new token, `#8c806a` light / `#6b6250` dark | `border-line-strong` on `paper`, light: **3.29:1** | 3:1 (non-text/UI) | PASS |
| Added | `--line-strong` | (same token, dark value) | `border-line-strong` on `paper`, dark: **3.05:1** | 3:1 (non-text/UI) | PASS |

`--accent-button` exists specifically because plain `--accent` (`#9c6b30`) on `--paper` didn't clear text contrast requirements when used as a button fill with `text-paper` on top — `Button`'s `primary` variant uses `bg-accent-button`, not `bg-accent`. `--line-strong` exists because plain `--line` is a decorative-divider color that doesn't meet the 3:1 non-text contrast ratio required for interactive element borders — it's used on `Button`'s `secondary` variant, `IconButton`'s bordered state, and `TextField`'s input border. Plain `--line` remains correct and unchanged for purely decorative dividers (section borders, footer separators).

## 2. Type, tracking, leading, container, and motion tokens

Sourced from the `@theme inline` block in `app/globals.css`.

### Font family

| Token | Value | Utility | Purpose |
|---|---|---|---|
| `--font-serif` | `var(--font-newsreader)` → `"Newsreader", ui-serif, Georgia, serif` | `font-serif` | Word display and long-form/reading content |
| `--font-sans` | `var(--font-work-sans)` → `"Work Sans", ui-sans-serif, system-ui, sans-serif` | `font-sans` | Everything else (UI chrome, labels, buttons, body text) |

### Type size

| Token | Value | Utility | Purpose |
|---|---|---|---|
| `--text-micro` | `11px` | `text-micro` | Accessibility floor for the smallest labels (replaced 9/9.5/10/10.5/11px arbitrary values scattered across `CollectionScreen.tsx`) — used by `Eyebrow` |
| `--text-display` | `44px` | `text-display` | Word headline size, between Tailwind's `text-4xl` (36px) and `text-5xl` (48px) — used by `ArrivalHero`'s word display |

Other sizes (`text-sm`, `text-base`, `text-lg`, `text-2xl`, `text-4xl`, etc.) use Tailwind's built-in scale; no custom token was needed for those.

### Letter spacing (tracking)

| Token | Value | Utility | Purpose |
|---|---|---|---|
| `--tracking-headline` | `-0.015em` | `tracking-headline` | Tight tracking on large serif headlines (e.g. `CollectionScreen`'s `h1`) |
| `--tracking-label` | `0.06em` | `tracking-label` | Slight spread for small UI labels (e.g. `ToggleGroup` chip text) |
| `--tracking-eyebrow` | `0.1em` | `tracking-eyebrow` | Default `Eyebrow`-style spacing |
| `--tracking-eyebrow-wider` | `0.12em` | `tracking-eyebrow-wider` | Wider eyebrow spacing variant |
| `--tracking-section` | `0.18em` | `tracking-section` | Widest spacing, for section-group labels |

These are deliberately named `tracking-eyebrow(-wider)`/`tracking-section` rather than Tailwind's own `tracking-wide`/`wider`/`widest`, because those built-in names are already used elsewhere in the app (`StoryView.tsx`, `PuzzleGame.tsx`) with Tailwind's default values (0.025em/0.05em/0.1em) — reusing those names here would have silently overridden Tailwind's defaults everywhere.

### Line height (leading)

| Token | Value | Utility | Purpose |
|---|---|---|---|
| `--leading-display` | `1.05` | `leading-display` | Tight leading for large word-display headlines |
| `--leading-body` | `1.5` | `leading-body` | Body/paragraph leading for serif reading text |

Tailwind's built-in `leading-relaxed` (1.625) is also used directly (e.g. `TodayHero`'s teaser, `ArrivalHero`'s long-form paragraph) for the "long reading paragraph" case — it did not need a custom token.

### Container widths

| Token | Value | Utility | Purpose |
|---|---|---|---|
| `--container-page` | `40rem` (640px) | `max-w-page` | Page-shell standard width (used across `HistoryList`, `PuzzleGame`, `StoryView`, `Header`, `Footer`, `ArrivalHero`, `TodayHero`, etc.) |
| `--container-form` | `27.5rem` (440px) | `max-w-form` | Narrower form-shell width (used on `login`, `account`, `unsubscribed` pages, `CollectionScreen`) |

The existing `46ch` prose measure (used in a few places, e.g. `ArrivalHero`'s paragraph) is a text-measure unit, not a layout width, and was deliberately not tokenized.

### Motion

| Token | Value | Usage |
|---|---|---|
| `--duration-theme` | `250ms` | Consumed directly via `var(--duration-theme)` in the `body` rule's `transition` (theme light/dark fade). Deliberately **not** registered in `@theme inline` — it doesn't back a generated Tailwind utility class, and is intentionally its own value rather than reusing Tailwind's default interactive-element transition (150ms), because a full light/dark swap reads better slower than a hover state does. |

## 3. Primitives (`components/ui/`)

### `Button` (`components/ui/Button.tsx`)

**Props:**
- `variant?: "primary" | "secondary" | "ghost" | "link"` (default `"primary"`)
- `size?: "sm" | "md"` (default `"md"`) — ignored for `ghost`/`link` (they keep their natural inline size, no padding applied)
- `disabled?: boolean`
- `loading?: boolean` — also disables the button (`disabled={disabled || loading}`)
- `fullWidth?: boolean` — applies `w-full`
- `className?: string` — merged in last, so it can override defaults
- Plus all native `<button>` props except `className`/`disabled` (which are re-typed above)

**Variants:**
| Variant | Classes | Use |
|---|---|---|
| `primary` | `rounded-full bg-accent-button font-medium text-paper transition-opacity hover:opacity-90 disabled:opacity-50` | Filled CTA |
| `secondary` | `rounded-full border border-line-strong text-ink-soft transition-colors hover:border-accent hover:text-ink` | Bordered secondary action |
| `ghost` | `text-ink-soft transition-colors hover:text-ink` | Unpadded inline text action |
| `link` | `text-ink-faint underline underline-offset-2 transition-colors hover:text-ink-soft` | Inline text link styled as a button |

**States:** `disabled:cursor-not-allowed` always applied; `disabled:opacity-50` only on `primary`. Focus is handled globally via `:focus-visible` in `app/globals.css` (a 2px accent-colored outline), not per-component.

**Accessibility notes:** it's a native `<button>`, so keyboard activation, `disabled` semantics, and focus are all native. No `aria-label` is added automatically — callers relying on icon-only content inside a `Button` need to supply their own accessible text (in practice, `Button` is always used with visible text or `aria-pressed`/`aria-label` supplied via `...rest`, e.g. `StoryView.tsx`'s favorite button passes `aria-pressed={isFavorited}`).

**Real example** (`components/HistoryList.tsx:199-206`, the deliberate full-width, non-pill exception — see §4):
```tsx
<Button
  variant="secondary"
  fullWidth
  className="mt-6 !rounded-md"
  onClick={() => setVisibleCount((c) => c + PAGE_SIZE)}
>
  Show more
</Button>
```

Another real example (`app/login/page.tsx:90-92`):
```tsx
<Button type="button" fullWidth className="mt-6" onClick={() => openMailProvider(matched)}>
  Open {matched.label}
</Button>
```

`ghost`/`link` needed extra call-site classNames in a few spots — e.g. `components/CollectionScreen.tsx:224-228` overrides `link`'s default underline/color for a "clear filter" action:
```tsx
<Button
  variant="link"
  className="!text-accent !no-underline text-micro tracking-eyebrow uppercase"
  onClick={() => onToggleLanguage(activeLanguage!)}
>
  clear
</Button>
```

### `IconButton` (`components/ui/IconButton.tsx`)

**Props:**
- `label: string` — **required**, becomes `aria-label`. Not optional, because an icon-only control with no accessible name is invisible to screen readers regardless of appearance.
- `children: React.ReactNode` — the icon (and optionally adjacent visible text, see `ThemeToggle` below)
- `className?: string`
- `bordered?: boolean` (default `true`) — toggles the bordered-pill look vs. a borderless icon-only control
- Plus native `<button>` props except `className`/`aria-label`

**Base classes:** `inline-flex min-h-11 min-w-11 cursor-pointer items-center justify-center gap-1.5 rounded-full px-2.5 text-ink-soft transition-colors hover:text-ink`. `min-h`/`min-w` (not `h`/`w`) is deliberate — it enforces the 44px minimum tap target while allowing a caller that also renders visible text next to the icon (e.g. `ThemeToggle`) to grow wider without being force-squared.

**`bordered` state:** when `true` (default), adds `border border-line-strong hover:border-accent`. `HistoryList`'s favorite-heart icon button explicitly sets `bordered={false}` for a borderless inline control.

**Accessibility notes:** `aria-label` is mandatory via the required `label` prop. The 44×44px minimum tap target (`min-h-11 min-w-11`) meets WCAG 2.5.5/2.5.8 target-size guidance.

**Real example, bordered (default)** — `components/ThemeToggle.tsx:30-41`:
```tsx
<IconButton
  label={`Theme: ${current.label}. Click to change.`}
  title={`Theme: ${current.label}`}
  onClick={cycle}
  className="sm:px-3"
>
  <Icon size={16} strokeWidth={1.75} />
  <span className="hidden font-sans text-xs sm:inline">{current.shortLabel}</span>
</IconButton>
```

**Real example, `bordered={false}`** — `components/HistoryList.tsx:178-189`:
```tsx
<IconButton
  label={favorited ? "Remove from favorites" : "Add to favorites"}
  onClick={() => handleToggle(word.slug)}
  bordered={false}
  className="shrink-0 !text-ink-faint hover:!text-accent"
>
  <Heart
    size={16}
    strokeWidth={1.75}
    className={favorited ? "fill-accent text-accent" : ""}
  />
</IconButton>
```

### `TextField` (`components/ui/TextField.tsx`)

**Props:**
- `label?: string` — renders an associated `<label>` above the input
- `error?: string` — renders a `role="alert"` message below the input and sets `aria-invalid`/`aria-describedby` on the input
- `icon?: React.ReactNode` — renders a leading icon inside the input (adjusts padding: `pl-9 pr-3` vs. plain `px-4`)
- `className?: string` — applied to the `<input>` element
- Plus native `<input>` props except `className` (uses React's `useId()` for a stable id when none is supplied)

**Base classes:** `w-full rounded-full border border-line-strong bg-transparent py-2.5 font-sans text-sm text-ink placeholder:text-ink-faint`. No `focus:border-accent` — the global `:focus-visible` ring (in `app/globals.css`) already provides a visible focus indicator, and a duplicate `:focus` border-color change would also fire on mouse clicks, not just keyboard focus.

**States:** invalid (`aria-invalid`, red `role="alert"` message in `text-danger`), with-icon (adjusted padding), label (optional).

**Accessibility notes:** label uses `htmlFor`/`id` association (`useId()`-generated if no `id` prop given); error text is linked via `aria-describedby` and announced via `role="alert"`.

**Real example** (`components/HistoryList.tsx:127-133`):
```tsx
<TextField
  icon={<Search size={15} strokeWidth={1.75} />}
  value={query}
  onChange={(e) => setQuery(e.target.value)}
  placeholder="Search words…"
  aria-label="Search words"
/>
```

**Real example with label** (`app/login/page.tsx:114-` — email input):
```tsx
<TextField
  id="email"
  name="email"
  type="email"
  inputMode="email"
  ...
/>
```

### `SegmentedControl` (`components/ui/SegmentedControl.tsx`)

This file exports two distinct components with different ARIA semantics — they render similarly but mean different things: `SegmentedTabs` selects one mutually-exclusive view (`role="tablist"`/`role="tab"`/`aria-selected`); `ToggleGroup` is a set of independently on/off filters (`aria-pressed` per segment).

#### `SegmentedTabs<T>`

**Props:**
- `segments: { key: T; label: string }[]`
- `active: T`
- `onChange: (key: T) => void`
- `className?: string`

Renders a `role="tablist"` container of `role="tab"` buttons; the active segment gets `aria-selected={true}`, `bg-paper-raised text-ink`; inactive segments get `text-ink-soft hover:text-ink`. Each tab has `min-h-11` for tap-target size.

**Accessibility notes:** proper `tablist`/`tab`/`aria-selected` roles for assistive tech; does not implement roving-tabindex/arrow-key navigation — activation is click/Enter/Space only (native button semantics).

**Real example** (`components/HistoryList.tsx:136`):
```tsx
<SegmentedTabs segments={tabs} active={filter} onChange={setFilter} className="mb-6" />
```

#### `ToggleGroup<T>`

**Props:**
- `segments: T[]` — full objects, not bare keys
- `getKey: (segment: T) => string`
- `isActive: (segment: T) => boolean`
- `onToggle: (segment: T) => void`
- `renderSegment: (segment: T, active: boolean) => ReactNode`
- `getButtonProps?: (segment: T, active: boolean) => ButtonHTMLAttributes<HTMLButtonElement>` — optional per-segment button attributes (title, aria-label, inline `style`, extra `className`)
- `className?: string`

This signature is richer than a simple key-list toggle because `CollectionScreen`'s language filter needs per-segment inline `style` (proportional flex-sizing) and `aria-label` attached directly to the `<button>`, not a nested child.

**Accessibility notes:** each button gets `aria-pressed={active}` and `type="button"`.

**Real example, proportional bar rendering** (`components/CollectionScreen.tsx:170-190`):
```tsx
<ToggleGroup
  segments={languages}
  getKey={(stat) => stat.name}
  isActive={(stat) => activeLanguage === stat.name}
  onToggle={(stat) => onToggleLanguage(stat.name)}
  renderSegment={() => null}
  getButtonProps={(stat, isActive) => ({
    title: stat.name,
    "aria-label": `Filter by ${stat.name}, ${stat.count} ${pluralize(stat.count, "word")}`,
    className: "transition-[opacity,background-color] duration-150",
    style: {
      flexGrow: stat.count,
      flexShrink: 1,
      flexBasis: 0,
      minWidth: 3,
      backgroundColor: isActive ? "var(--accent)" : "currentColor",
      opacity: activeLanguage ? (isActive ? 1 : 0.09) : stat.opacity,
    },
  })}
  className="mt-3.5 flex h-7 gap-0.5 text-ink"
/>
```

**Real example, chip-list rendering** (`components/CollectionScreen.tsx:192-214`):
```tsx
<ToggleGroup
  segments={languages}
  getKey={(stat) => stat.name}
  isActive={(stat) => activeLanguage === stat.name}
  onToggle={(stat) => onToggleLanguage(stat.name)}
  renderSegment={(stat) => (
    <>
      <span>{stat.name}</span>
      <span className="text-micro opacity-70">{stat.count}</span>
    </>
  )}
  getButtonProps={(stat, isActive) => ({
    className: clsx(
      "relative flex items-baseline gap-1.25 rounded-full border px-2.25 py-1.25 font-sans text-micro tracking-label transition-colors duration-150 after:absolute after:-inset-3 after:content-['']",
      isActive ? "border-accent text-accent" : "border-line-strong text-ink-soft"
    ),
  })}
  className="mt-3 flex flex-wrap gap-1.5"
/>
```

### `Eyebrow` (`components/ui/Eyebrow.tsx`)

**Props:**
- `as?: "span" | "p"` (default `"span"`)
- `className?: string`
- `children: React.ReactNode`
- Plus native `HTMLAttributes<HTMLElement>`

**Base classes:** `font-sans text-micro uppercase text-ink-soft`.

A small, single-purpose primitive: a polymorphic (`span`/`p`) uppercase micro-label. It has no variants or interactive states — styling differences (tracking, color, spacing) are applied per call site via `className`.

**Accessibility notes:** none beyond correct semantic tag choice (`p` for a block-level subline vs. `span` for inline labels); no ARIA roles needed since it's plain text content.

**Real examples** (`components/CollectionScreen.tsx`):
```tsx
<Eyebrow as="p" className="mt-2.5 tracking-eyebrow-wider">
  {subline}
</Eyebrow>
```
```tsx
<Eyebrow className="tracking-eyebrow">tap to filter</Eyebrow>
```
```tsx
<Eyebrow as="p" className="pt-6.5 pb-1 tracking-section">
  {group.label}
</Eyebrow>
```

Also used for the hero's dateline (`components/ArrivalHero.tsx:45-47`):
```tsx
<Eyebrow as="p" className="tracking-eyebrow-wider text-accent">
  Today&apos;s word &middot; {date}
</Eyebrow>
```

## 4. Rules that aren't obvious from the code alone

**Pill-by-default border radius, with one deliberate exception.** Every interactive control in the design system defaults to `rounded-full` (a true pill): `Button`'s `primary`/`secondary` variants, `IconButton`, `TextField`'s input, `SegmentedTabs`' tabs, `ToggleGroup`'s chip-list rendering. The **one** deliberate exception is `HistoryList`'s "Show more" button, which overrides this with `!rounded-md` (`components/HistoryList.tsx:199-206`) because a full-width pill-shaped button reads oddly at that width — it's a conscious, single-instance deviation, not a missed migration. Do not treat any other square-cornered button as intentional; check whether it should instead be using the pill default.

**Newsreader (serif) vs. Work Sans (sans).** `font-serif` (Newsreader) is reserved for word display and long-form/reading content: the daily word itself (`ArrivalHero`'s `h1`, `CollectionScreen`'s word list), headings that read as editorial copy, italic captions/teasers, and body paragraphs meant to be read at length. `font-sans` (Work Sans) is the default for everything else — UI chrome, buttons, labels, form inputs, navigation, dates/metadata. `body` in `app/globals.css` sets `font-family: var(--font-work-sans), ...` as the page default, so `font-serif` is always applied explicitly at the call site where serif is wanted, never the other way around.

**`ink-soft`/`ink-faint` usage split.** See §1 above for the full token guidance. In short: `ink-soft` for secondary text (supporting copy, inactive states), `ink-faint` for tertiary text (labels, metadata, placeholders) — the two currently share the same computed color in both themes after the Phase 3 contrast fix, but remain semantically distinct in the code and should not be treated as freely interchangeable.

**`components/AdminDashboard.tsx` is out of scope.** It predates the design-system consolidation and was explicitly excluded from every phase (tokens, primitives, contrast fixes). It still uses raw Tailwind arbitrary values throughout — e.g. `text-[32px]`, `leading-[1.05]`, `tracking-[-0.015em]`, `mt-[36px]`, `text-[13.5px]` — and plain `border-line` where the rest of the app now uses `border-line-strong` on interactive elements. None of the `components/ui/` primitives are used there. Do not use it as a reference when building new UI, and do not "fix" it as a drive-by change — any future consolidation of `AdminDashboard.tsx` is its own separate, deliberate scope decision.
